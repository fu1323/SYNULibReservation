#某学校（如沈阳师范大学）图书馆座位预约系统的自动化预约实现（利用了联创服务器用客户端302传unionid给学校服务器的问题,本程序绕过了密码登陆,直接用unionid换token） 针对杭州联创的系统  <br>
##使用说明<br>
请自行编译，java -jar xxx.jar 可看到效果，初次运行会生成json配置文件，抓包填写即可 <br>
renew字段默认false，改成true可自动续期（仅macos、LINUX,自动续期对windows无效 因为使用了at命令 windows逻辑请自行处理）<br>
座位可填写多个不限制，当程序运行发现座位被占用会依次尝试<br>
unionid 座位id(devSn)可通过抓包获得，自己微信扫桌子上的二维码的时候抓包即可<br>
续期通常自动执行(实际是java -jar xxx.jar renew，开启续期会自动生成renew.json,同时插入at自动任务 <br>图书馆闭馆时间是晚上十点，而单次最大预约市场五小时，所以若在下午四点之后 程序执行将不会再排今天的续期定时任务)<br>
程序自动续期只对一天有效，如果想每天自动执行 无感预约 请配合crontab使用<br>

配置文件参考:<br>
```
{ "unionid":"xxxxxxx",  抓包获取自己的unionid 
                    "seatid":[  座位优先级列表  id后面跟着的序号是优先级 越小越优先
                      {"id0": "","comment":"A-123"},  id位置填写心仪座位的devsn  comment字段程序不会读取，给人看的，知道这是哪个座位
                      {"id1": "","comment":"4F A-123"},
                      {"id2": "","comment":"3F B-567"}
                    ],
                       "autorenew": "false", 自动续期开关 改成true可以打开（注意true是字符串true） 续期功能由于调用了at命令，故不支持windows
                       "renew_gap_minute":"3", 预约结束到再次签到的间隔分钟数，经过测试 系统预约结束之后 正式释放到再次可以预约之间有一两分钟延迟，故在本程序这里控制，建议不要小于3
                       "stop_renew_hour": "16",几点之后运行程序（包含手动运行和自动续期自动运行)的时候，不再安排今天的续期（默认16点 因为16点续期成功之后 5小时到期的时候就是21点）
                       "stop_renew_minute": "00", 对应分钟数
                       "fallback": "false", 回落设置，即续期开启时，程序在续期模式运行时，发现座位无法续期（比如被别人预约了导致自己签到的时候不足5小时时，程序不退出，而是换座位从头开始寻找列表里面能预约成功的座位）
                       "allfail": {     控制当正常预约或续期触发fallback回落时 心仪座位列表没有可用座位的时候，延期等待一定时间之后从头重试座位部分的逻辑
                           "fallback": "false",  开关
                           "delayminute": "15",  延期等待的时间
                           "maxtrycount": "3"    最大尝试次数，当超过时程序将放弃并完全退出    最大尝试次数建议不要设置太大，延期等待时间建议不要设置太小，防止冲击图书馆服务器，做一个有素质的人
                         }
                    }

```
